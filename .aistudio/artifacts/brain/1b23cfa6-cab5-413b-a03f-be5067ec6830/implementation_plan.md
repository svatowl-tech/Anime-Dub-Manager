# Модуль VST3-обработки звука с нативным интерфейсом плагинов

Разработка полноценного модуля конвейера сведения для подключения сторонних студийных **VST3-плагинов** (таких как **iZotope Ozone**, **FabFilter Pro-Q / Pro-DS**, **Waves**, **TDR** и др.) с открытием их оригинального графического окна (Native GUI), сохранением бинарного состояния плагина внутри проекта, быстрым рендером тестового фрагмента для предпрослушивания и поддержкой поканальной, индивидуальной и шинной маршрутизации по правилам приложения.

---

## Согласованные архитектурные решения

> [!IMPORTANT]
> Ниже зафиксированы ключевые продуктовые решения, подтвержденные перед проектированием архитектуры:

- **Одиночный VST3-плагин на один шаг конвейера**: Каждый шаг модуля отвечает ровно за один `.vst3` плагин и создает собственную нумерованную папку шага (`XX_vst3_...`). Для построения цепочки из нескольких VST3-приборов в конвейер сведения последовательно добавляется несколько шагов модуля.
- **Быстрый рендер короткого фрагмента по кнопке превью**: Настройка звука выполняется в нативном окне плагина, а для контроля результата доступна кнопка быстрого рендера активного голосового участка (5–15 секунд) с мгновенным сравнением «До / После (A/B)» без необходимости рендерить всю 24-минутную серию.
- **Гибкая схема маршрутизации дорожек (3 режима)**:
  1. *Пакетно (единый слепок плагина на все выбранные дорожки дабберов)*;
  2. *Индивидуально (персональное окно и состояние VST3 под каждую дорожку/актера)*;
  3. *Групповая шина / Мастер (обработка склеенной шины голосов или финального микса, идеально для iZotope Ozone)*.

---

## 1. Обзор и концепция работы модуля

- **Что делает модуль**: Позволяет звукорежиссеру или таймеру вставить любой установленный в системе 64-битный плагин стандарта **VST3** в любую точку конвейера сведения (после нейросетевой очистки DeepFilterNet, перед компрессией или на финальном мастере). Модуль открывает родное окно плагина (со всеми анализаторами спектра, кривыми эквализации и модулями внутри iZotope Ozone), автоматически захватывает полный бинарный слепок настроек (`raw_state`) после закрытия или сохранения окна и рендерит 24-bit / 48 kHz WAV-файлы по строгим правилам манифеста серии.
- **Для кого предназначен**: Для звукорежиссеров, релиз-менеджеров и продвинутых таймеров, которым требуется фирменное звучание любимых коммерческих VST3-инструментов внутри автоматизированного конвейера без ручного переноса проекта в стороннюю DAW.
- **Ключевая ценность**:
  - **Нативный интерфейс без урезания функций**: Открывается оригинальное окно VST3-плагина со всеми встроенными ассистентами (например, *Ozone Master Assistant*, *FabFilter Pro-Q Spectrum Grab*).
  - **Полная совместимость с правилами конвейера**: Модуль берет входные WAV-дорожки из предыдущего активного шага, сохраняет обработанные дорожки в изолированную директорию шага и передает их дальше (включая «Экспорт звукорежиссеру в FLAC» и сборку мастер-видео).
  - **Надежная изоляция процессов**: Хостинг VST3-плагина и открытие его окна выполняются в изолированном процессе движка (`pedalboard` C++/JUCE внутри рабочего окружения), поэтому сбой стороннего плагина никогда не приведет к падению основного окна приложения.

## 2. Пользовательский опыт и визуальный дизайн

### Ключевые пользовательские сценарии

1. **Сканирование и выбор VST3-плагина**:
   - При добавлении модуля **«VST3 Плагин (Нативный интерфейс)»** в конвейер сведения пользователь выбирает плагин из автоматически найденного каталога системных папок (`Common Files/VST3`, `/Library/Audio/Plug-Ins/VST3`, `~/.vst3`) или указывает путь к файлу `.vst3` вручную через кнопку «Обзор `.vst3`...».
   - Для удобства предусмотрен быстрый поиск по названию и фильтр по производителю.

2. **Выбор режима маршрутизации дорожек**:
   - **Режим «Все дорожки (Единый пресет)»**: Настраивается одно окно VST3, после чего выбранные галочками дорожки дабберов поочередно проходят через этот плагин.
   - **Режим «Индивидуально по дабберам»**: Напротив каждой дорожки даббера отображается собственная кнопка **«Открыть GUI плагина»** и индикатор статуса настройки (`Настроен` · `По умолчанию` · `Пропуск`). Это позволяет, например, повесить эквалайзер или деэссер и настроить его под тембр каждого актера отдельно.
   - **Режим «Шина голосов / Мастер»**: Модуль автоматически принимает склеенную шину голосов (`voices_master`) или предварительно суммирует активные дорожки для мастеринговой обработки в iZotope Ozone.

3. **Работа с нативным окном VST3 и быстрое превью фрагмента**:
   - Нажатие кнопки **«Открыть окно VST3 (Native GUI)»** запускает нативное окно плагина поверх приложения.
   - В блоке **«Быстрое превью фрагмента»** пользователь выбирает целевую дорожку, длительность фрагмента (`10 сек` или `15 сек`) — система автоматически находит участок с активной речью (по пикам энергии, чтобы не рендерить тишину) либо берет указанный таймкод.
   - При нажатии **«Рендер превью»** за 1–2 секунды создается временный обработанный фрагмент, доступный для прослушивания во встроенном мини-плеере с мгновенным переключателем **«Оригинал (До) / С плагином (После)»**.

4. **Управление слепками состояний и пользовательскими пресетами**:
   - Полное внутреннее состояние VST3-плагина (включая все внутренние суб-модули iZotope Ozone) автоматически сериализуется в Base64-слепок внутри манифеста серии, а также может быть сохранено в библиотеку пресетов приложения под собственным именем (например, *«Ozone — Плотный мастер аниме»*).

### Визуальная система и компоновка карточки модуля

- **Эстетика и палитра**: Инженерная студийная консоль в темной палитре приложения (`bg-neutral-950` основной фон, `bg-neutral-900` структурные блоки, `border-neutral-800` тонкие 1px границы без вложенных рамок, акцентные элементы `indigo-500` для активного хоста и `emerald-400` для подтвержденного слепка состояния).
- **Типографика и численные данные**: Строгое выравнивание всех таймкодов, частоты дискретизации (`48.0 кГц · 24-bit`), длительности и размеров файлов моноширинным шрифтом с табличными цифрами (`font-mono tabular-nums`). Статические метаданные плагина (формат, вендор, размер слепка состояния) выводятся чистым текстом через разделитель `·` без декоративных капсул.
- **Интерактивные состояния**:
  - Во время открытия нативного окна VST3 карточка модуля показывает спокойный статус *«Окно плагина открыто — настройте параметры и закройте окно для сохранения слепка»* с кнопкой принудительного завершения.
  - Во время рендера превью или полного шага отображается прогресс-бар с указанием текущей обрабатываемой дорожки даббера.

## 3. Ключевые архитектурные решения и компромиссы

- **Решение 1: Изолированный VST3-хост на базе C++/JUCE движка (`pedalboard`) в отдельном процессе**
  - *Выбранный подход*: Вызов `pedalboard.load_plugin()` в выделенном Python-сайдкар процессе для открытия нативного окна (`show_editor()`) и пакетного рендера аудио с передачей состояния через бинарный `raw_state`.
  - *Почему*: Сторонние VST3-плагины работают с нативной памятью ОС и графическими контекстами OpenGL/Direct2D. Запуск их в отдельном процессе гарантирует 100% защиту основного процесса Electron от зависаний и конфликтов потоков GUI, а `pedalboard` уже входит в состав нашего портативного окружения `ai_env`.
  - *Отклоненные альтернативы*: Прямая компиляция Node C++ аддона внутри процесса Electron (высокий риск падения всего приложения при ошибке внутри любого стороннего VST3-плагина и проблемы с подписью/пересборкой под разные версии Electron).

- **Решение 2: Хранение состояния через полный бинарный чанк `raw_state` (.vstpreset совместимый)**
  - *Выбранный подход*: Сохранение полного бинарного слепка состояния плагина (`plugin.raw_state` в Base64 / `.vststate` файле в папке проекта) вместо сохранения только плоского списка VST-параметров.
  - *Почему*: Комплексные плагины вроде **iZotope Ozone**, **Neutron**, **RX** или **FabFilter Pro-Q 3** хранят динамическое число полос эквалайзера, кривые обучения Master Assistant и внутренние маршруты исключительно во внутреннем бинарном чанке состояния, а не в простых числовых параметрах. Использование `raw_state` гарантирует 100% точное восстановление всех настроек плагина при повторном открытии окна и при пакетном рендере.

- **Решение 3: Автоматический поиск речевого фрагмента для быстрого превью**
  - *Выбранный подход*: При нажатии «Быстрое превью» анализатор автоматически выбирает 10-секундное окно на дорожке даббера, где присутствует плотная речь (либо использует заданный пользователем интервал времени), прогоняет только этот срез через VST3 с прогревом буфера (`tail/warmup` 0.5 сек) и отдает в плеер сравнения До/После.
  - *Почему*: Дорожки дабберов часто содержат длинные паузы в начале серии; автопоиск активной фразы экономит время звукорежиссера и сразу дает услышать работу плагина на реальном голосе.

### Модель данных шага в манифесте сведения

Каждый шаг модуля `vst3_rack_processor` в `mixing_manifest.json` хранит следующую структуру параметров:
- **`vst3Path`**: Абсолютный путь к выбранному `.vst3` плагину.
- **`pluginName` / `vendor`**: Читаемое имя и производитель плагина.
- **`routingMode`**: `'batch_all'` (единый пресет на выбранные дорожки) | `'per_track'` (индивидуальное состояние под каждую дорожку) | `'master_bus'` (обработка склеенной шины голосов или мастер-дорожки).
- **`selectedTrackKeys`**: Список ключей дорожек, включенных для обработки на этом шаге (с возможностью снять галочку с любой дорожки, которую нужно пропустить без изменений).
- **`globalStateFile`**: Путь к бинарному файлу слепка состояния (`.vststate`) для пакетного или шинного режима.
- **`perTrackStateFiles`**: Словарь `{ [trackKey]: pathToVstState }` для индивидуального режима настройки под каждого даббера.
- **`wetMixPercent` и `outputGainDb`**: Параллельный подмес (`Dry/Wet` от 0% до 100%, полезно если в самом плагине нет ручки Mix) и выходная компенсация уровня (`-12` ... `+12 дБ`) с защитой от клиппинга.
- **`resetBetweenTracks`**: Сброс внутренних буферов реверберации/дилея плагина перед началом каждой новой дорожки даббера.

### Поток состояний и обработка ошибок

1. **Сканирование плагинов (`mixing-scan-vst3-plugins`)**:
   - Сканирует стандартные системные директории VST3 на текущей ОС и пользовательские папки, возвращая список доступных `.vst3` бандлов без их тяжелой инициализации в памяти.
2. **Открытие нативного интерфейса (`mixing-open-vst3-editor`)**:
   - Передает путь к `.vst3` и путь к текущему файлу `.vststate` (если плагин уже настраивался ранее).
   - Python-сайдкар открывает нативное окно `plugin.show_editor()`. Как только пользователь закрывает окно плагина, сайдкар автоматически выгружает обновленный `plugin.raw_state` на диск и возвращает в UI подтверждение со временем обновления и размером слепка.
3. **Быстрый рендер превью (`mixing-preview-vst3-snippet`)**:
   - Вырезает выбранный 10–15 секундный речевой участок исходной дорожки (с 0.5 сек пред-буфером для корректного срабатывания компрессоров/лимитеров внутри Ozone), прогоняет через VST3 с текущим `.vststate` и возвращает пару временных WAV-файлов (`До` и `После`) для мгновенного A/B прослушивания в карточке модуля.
4. **Полный рендер шага в конвейере (`_execVst3Plugin`)**:
   - Проходит по всем входным дорожкам предыдущего шага конвейера.
   - Для отмеченных дорожек применяет VST3-плагин в 32-bit float с сохранением точной по-сэмпловой длины дорожки и сохраняет результат в папку шага (`XX_vst3_<ИмяПлагина>/...`) в формате 24-bit 48 kHz WAV.
   - Для снятых с выбора дорожек (если пользователь отключил обработку конкретного актера) аккуратно передает дорожку в выходную папку шага без изменений, чтобы на следующих шагах конвейера и при экспорте звукорежиссеру сохранялся полный комплект дорожек серии.
