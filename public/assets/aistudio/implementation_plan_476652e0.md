# План реализации: Umbrel OS Server Mode, AI-агент куратора и веб/мобильный тонкий клиент

Краткое резюме: существующий серверный слой приложения эволюционирует в полноценный автономный бэкенд-движок для **Umbrel OS** с поддержкой тяжелых медиа- и AI-пайплайнов (`FFmpeg`, `yt-dlp`, `WebTorrent`, `Python AI_env`), защищенным доступом с компьютера и телефона через браузер, полным набором инструментов управления для локального AI-агента (**MCP Streamable HTTP/SSE + stdio + CLI + REST API**) и двусторонним **Центром уведомлений и подтверждений куратора** (встроенный Web Inbox + существующий Telegram-бот). Вся текущая десктопная Electron-версия (Windows / macOS / Linux) и её сборки остаются **на 100% нетронутыми и рабочими**.

---

## Согласованные решения и ключевые параметры (User Review)

По итогам уточняющего интервью зафиксированы следующие архитектурные решения:
- **Упаковка для Umbrel OS и GitHub Release**: мультиархитектурный Docker-образ в **GHCR** (`ghcr.io/<owner>/<repo>`) + готовый манифест **Umbrel Custom App Store** (включая описание магазина приложений, карточку приложения и `docker-compose` шаблон с постоянным томом данных), публикуемый автоматически в CI/CD параллельно с десктопными релизами.
- **Интерфейс управления для локального AI-агента**: полный тройной стек — **MCP-сервер** (одновременно **Streamable HTTP / SSE** для сетевых агентов на Umbrel и **stdio** для локального запуска) + **CLI-утилита** с предсказуемым JSON-выводом + **REST API с OpenAPI-спецификацией** и готовым руководством-плейбуком для агента.
- **Уведомления, пометки и подтверждения куратора**: встроенный **Web Inbox** в браузерном/мобильном интерфейсе **плюс** интеграция с существующим **Telegram-ботом / MTProto**, синхронизированные между собой.
- **Аппаратный профиль сервера и AI-рантайм**: **Multi-arch `linux/amd64` (`x86_64`) и `linux/arm64` (`ARM64`)** с полной поддержкой `Python AI_env` (`Whisper`, `DeepFilterNet3`, `Demucs`, локальный перевод, диаризация) внутри контейнера и на ARM64/x86_64.

Дополнительные рекомендуемые значения по умолчанию (при необходимости легко меняются до начала сборки):
- Идентификатор приложения в Umbrel App Store: `anime-dub-manager`, порт веб-интерфейса и MCP/API по умолчанию: `3000` (настраивается через переменную порта Umbrel).
- Авторизация при доступе по локальной сети / Tailscale / с телефона: встроенная защита по токену/PIN-паролю для веб-интерфейса и отдельный Bearer-токен для AI-агента (с безопасной первоначальной настройкой через экран приветствия или переменные окружения).

## 1. Концепция и сценарии работы

### Перенос вычислений на Umbrel OS, интерфейсы — везде
- **Сервер на Umbrel OS** становится единственным источником истины: хранит проекты, серии, участников, роли, пресеты, исходники видео, субтитры, дорожки даберов, фиксы, сведение и кеш моделей на постоянном серверном хранилище.
- **Компьютер и телефон** работают как **тонкие клиенты через браузер** (а существующее десктопное Electron-приложение при желании может оставаться локальным или подключаться к серверу без потери автономной работы).
- В серверном режиме отключаются заглушки/эмуляции веб-превью: все реальные контроллеры (скачивание с Anime365, торрентов Nyaa/TokyoTosho и YouTube, парсинг и чистка субтитров, автотайминг, QA через Whisper, шумоподавление DeepFilterNet / голос-изоляция, рендер видео, экспорт звукорежиссеру, автопостинг и скачивание дорожек из Telegram) выполняются на сервере в асинхронной очереди задач с живым прогрессом.

### Автономный AI-агент как «второй пилот» и исполнитель рутины куратора
Локальная LLM на сервере получает структурированные инструменты для полного цикла работы куратора без хрупкого парсинга интерфейса:
1. **Поиск и загрузка контента**: поиск тайтла (Shikimori / Anime365 / трекеры), скачивание равки (Anime365 Direct, WebTorrent, YouTube) и субтитров на сервер.
2. **Подготовка проекта и серий**: создание/обновление карточек проектов и серий, нормализация/чистка субтитров, извлечение надписей, извлечение фраз, автоматическое разбиение и назначение персонажей даберам на основе глобального маппинга и занятости.
3. **Приёмка и контроль качества**: сканирование входящих дорожек из Telegram-чатов/топиков, привязка к сериям и актерам, запуск аудио-анализа (клиппинг, шум, тишина) и Whisper QA, запуск автотайминга и экспорта звукорежиссеру.
4. **Эскалация на человека**: если агент сталкивается с неоднозначностью (сомнительное сопоставление роли, брак дорожки по QA, конфликт дедлайна, финальная публикация релиза или пометка спорного фрагмента), он создает задачу в **Curator Inbox** и присылает краткий запрос с действиями в **Web Inbox** и **Telegram**. Куратор ставит пометку, одобряет/отклоняет шаг или открывает серию в браузере в один клик — агент читает вердикт и продолжает работу.

## 2. Пользовательский опыт и визуальный дизайн (Desktop & Mobile)

### Единая рабочая среда: Компьютер (1440px+) и Телефон (375px–430px)
- **Эргономика без визуального шума**: придерживаемся сдержанной рабочей палитры (нейтральные темные/светлые поверхности, один акцент для первичного действия, моноширинные табличные цифры для таймингов, децибел, прогресса и размеров файлов, без декоративных градиентов и без россыпи цветных бейджей на карточках).
- **Строго один контейнер прокрутки**: зафиксированный каркас приложения (`100dvh`) без двойных скроллбаров; на широких экранах — компактный сворачиваемый левый сайдбар с проектами и инструментами, на телефоне (до `768px`) — адаптивная нижняя панель навигации с быстрыми переключателями («Проекты», «Задачи», «Входящие куратора», «Настройки») и крупными тач-целями от `44×44 px`.
- **Замена нативных файловых диалогов ОС в браузере**: в веб-режиме вместо отмененного системного диалога Electron появляется удобный **контекстный менеджер файлов сервера и загрузки с устройства**:
  - Загрузка видео, `.ass`/`.srt` субтитров и аудиодорожек/фиксов прямо из браузера ПК или с телефона (multipart streaming upload с прогрессом) в папку выбранной серии.
  - Просмотр файлов внутри выделенной рабочей директории сервера (для выбора уже скачанных торрентом или положенных в папку файлов) и скачивание готовых архивов/роликов/дорожек прямо в браузер через потоковые ссылки.
- **Curator Inbox (Входящие и пометки от AI-агента)**:
  - Доступен из шапки/нижней навигации с индикатором непрочитанных уведомлений, требующих реакции.
  - Карточка уведомления содержит суть от агента, контекст (проект, серия, дорожка, таймкод или список найденных проблем), статус (`Ожидает проверки`, `Одобрено`, `Отклонено`, `С пометкой`), поле для заметки куратора и мгновенный переход в нужную вкладку серии (субтитры, тайминг, даберы или QA) — никаких тупиковых экранов.
  - Десктопная панель деталей открывается в выдвижной боковой панели (drawer), не перегораживая рабочее полотно модальными окнами.
- **Экран авторизации тонкого клиента**: минималистичный вход по коду доступа / паролю сервера при обращении по сети, с мгновенным сохранением сессии и без показа технических логов или внутренних ID в интерфейсе.

## 3. Ключевые продуктовые решения и компромиссы

1. **Единый бэкенд-сервер поверх существующих контроллеров вместо переписывания логики**:
   - *Выбор*: расширить существующий серверный раннер (`server.ts`) режимом `ADM_SERVER_MODE`, который отключает веб-превью-заглушки, использует постоянный каталог `ADM_DATA_DIR`, включает потоковую загрузку/выдачу файлов и открывает REST + MCP + Inbox.
   - *Компромисс*: сохраняется 100% общая бизнес-логика с Electron (`ProjectController`, `ExportController`, `WhisperController`, `SyncController`, `TelegramController` и др.), не возникает расхождения версий и не ломается десктопная сборка. Стандартный локальный dev-превью без флага серверного режима остается быстрым и безопасным.
2. **Тройной слой для AI-агента (MCP Streamable HTTP/SSE + MCP stdio + CLI/REST)**:
   - *Выбор*: поддержать современный **MCP Streamable HTTP (`/mcp`)** вместе с обратной совместимостью **SSE (`/sse` + `/messages`)**, отдельный **stdio MCP-вход** и **CLI-команду** поверх того же API-движка.
   - *Компромисс*: любой локальный агент на Umbrel (в отдельном Docker-контейнере через HTTP/SSE, через `docker exec` по stdio, или bash-агент через CLI/REST) подключается без переходников и костылей, получая одинаковые JSON-схемы и валидацию.
3. **Двусторонний Web Inbox + Telegram для контроля куратора**:
   - *Выбор*: хранить журнал уведомлений, пометок и решений куратора на сервере, а при наличии настроенного Telegram-бота или MTProto дублировать запросы агента в личный чат/рабочую группу куратора с быстрыми командами/кнопками ответа.
   - *Компромисс*: даже если Telegram временно не подключен или заблокирован, Web Inbox в браузере и на телефоне продолжает работать полностью автономно; когда Telegram подключен — куратор реагирует прямо из мессенджера или с экрана блокировки.
4. **Multi-arch `linux/amd64` + `linux/arm64` сборка Docker + AI_env**:
   - *Выбор*: научить сборочный скрипт Python `AI_env` корректно различать `x86_64` и `aarch64/arm64` под Linux (CPU-пакеты PyTorch / Whisper / ONNX / DeepFilterNet / Demucs с системным `ffmpeg`), а GitHub Actions собирать и пушить мультиархитектурный образ в GHCR вместе с готовым каталогом манифестов Umbrel.
   - *Компромисс*: сборка образа с полным `AI_env` для двух архитектур занимает больше времени в CI (~15–25 мин через кэш слоев и Buildx), зато пользователь на любом железе Umbrel (Umbrel Home / Mini-PC на x86_64 или Raspberry Pi 5 на ARM64) устанавливает приложение в один клик с уже готовым AI-окружением из коробки.

### Модель данных и серверное хранение
- Все состояния хранятся на едином постоянном томе (`/data` в контейнере, примонтированном к `${APP_DATA_DIR}` в Umbrel OS): JSON-базы проектов, серий, участников, конфигурации, скачанные медиафайлы и рабочие папки проектов, кеш моделей `AI_env`, а также новый журнал `curator_inbox.json` для сообщений, пометок и решений между агентом и человеком.
- Для синхронизации между одновременными действиями AI-агента, браузера на ПК, телефона и фоновых задач сервера используется единый событийный поток **SSE**, уведомляющий UI об обновлении проектов, серий, очереди задач и новых сообщениях в **Curator Inbox**.

### Границы безопасности
- **Разделение прав доступа и сессий**: UI защищен токеном/паролем доступа куратора с `HttpOnly`-сессией или Bearer-авторизацией, а AI-агент подключается по отдельному настраиваемому `AGENT_TOKEN`; без валидной авторизации закрыты все IPC, REST, MCP и файловые маршруты.
- **Строгая изоляция файловой системы (Path Confinement)**: любые операции с файлами (загрузка, браузер папок, чтение медиа, экспорт, удаление) нормализуются и жестко проверяются на нахождение строго внутри разрешенной рабочей директории данных сервера (`ADM_DATA_DIR`), исключая выход за пределы контейнера (`path traversal`).
- **Секреты остаются на сервере**: токены Telegram-бота, сессия MTProto, куки Anime365/YouTube, токен Яндекс.Диска и HuggingFace хранятся исключительно на сервере и не утекают в открытые публичные ответы API.

### Инструменты AI-агента (MCP / CLI / REST)
Чтобы локальная модель на Umbrel уверенно заменяла куратора в рутине, ей предоставляются высокоуровневые доменные команды с четкими схемами входных данных и человекочитаемыми ответами:
- **Обзор и чтение**: список проектов, подробности проекта и серий, список участников и их занятость, статусы фоновых задач, чтение логов/отчетов QA и просмотр файлов в папке серии.
- **Поиск и скачивание**: поиск аниме на Anime365/Shikimori и торрентов на трекерах, запуск загрузки серии с Anime365, WebTorrent или YouTube (с ожиданием/опросом статуса задачи), загрузка субтитров.
- **Подготовка проекта и назначение даберов**: создание/обновление проекта и серии, импорт/чистка/конвертация субтитров, чтение реплик и ролей, массовое или точечное назначение даберов на персонажей, обновление статусов и дедлайнов, отправка уведомлений даберам в Telegram.
- **Обработка, QA и экспорт**: сканирование аудиодорожек из Telegram-чата/темы, запуск аудиоанализа и Whisper QA, запуск автотайминга и экспорта комплекта для звукорежиссера, подготовка/запуск рендера.
- **Коммуникация с куратором**: отправка уведомления или запроса на подтверждение в Curator Inbox (+ Telegram), чтение заметок и вердиктов куратора, установка или обновление статусной пометки на серии/проекте.
- **Встроенный Playbook (MCP Resource / Prompt + документация)**: пошаговая инструкция для LLM-агента — когда действовать автономно, как проверять зависимости шагов (например, сначала дождаться скачивания равки и субтитров, затем распределить роли), и в каких точках обязательно запрашивать проверку куратора.

### Упаковка Umbrel OS и автоматический релиз в GitHub Actions
- Расширение существующего пайплайна релизов дополнительным workflow (или job) для сборки **multi-arch** Docker-образа (`linux/amd64`, `linux/arm64`) с Node.js, системным `FFmpeg`, `yt-dlp` и предустановленным `Python AI_env`, с публикацией в `ghcr.io`.
- В репозитории появляется готовая структура **Umbrel Custom App Store** (каталог магазина, иконки/превью, `umbrel-app.yml`, `docker-compose.yml`), чтобы пользователь мог добавить репозиторий как источник приложений прямо в интерфейсе Umbrel OS и установить или обновить приложение на сервере одной кнопкой.
- Все существующие Electron workflow (Windows `.exe`, macOS `.dmg`, Linux `.AppImage`, архивы `AI_env`) сохраняются без изменений.
